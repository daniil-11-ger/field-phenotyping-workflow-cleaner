# Техническое приложение к статье

## 1. Назначение workflow

Разработанный workflow предназначен для воспроизводимой обработки полевых фенотипических данных кунжута (*Sesamum indicum* L.), полученных с использованием приложения Field Book. Основная цель технической реализации заключается в автоматизации перехода от сырых CSV-файлов к очищенному датасету, пригодному для последующего применения в селекционных моделях, включая BLUP, GBLUP и интеграцию с генотипическими данными.

## 2. Программная среда

Обработка данных выполняется в среде R/RStudio. Для анализа используются пакеты `tidyverse`, `janitor`, `lubridate`, `readr`, `stringr`, `lme4`, `broom.mixed` и `ggplot2`. Все этапы анализа разделены на независимые скрипты, что обеспечивает прозрачность, повторяемость и возможность проверки каждого шага.

## 3. Структура входных данных

Входными данными являются CSV-файлы, экспортированные из Field Book. Минимально необходимыми полями являются: уникальный идентификатор растения (`uuid`), название линии или аксессии (`entry`), блок опыта (`block`), координаты растения в поле (`row`, `column`), название признака (`trait`) и измеренное значение (`value`). Дополнительно могут использоваться поля `person`, `timestamp`, `device_name` и `notes`, позволяющие контролировать влияние оператора, времени измерения и технических условий сбора данных.

## 4. Основные этапы анализа

Первый этап включает импорт всех CSV-файлов из папки `data/raw` и их объединение в единый мастер-файл. На этом этапе выполняется стандартизация названий столбцов и первичная проверка структуры данных.

Второй этап выполняет очистку и преобразование данных. Значения признаков приводятся к числовому типу, удаляются дублирующиеся записи, а данные переводятся из длинного формата в широкий формат, где каждая строка соответствует отдельному растению, а каждый признак представлен отдельным столбцом.

Третий этап включает контроль качества данных. Рассчитываются доля пропущенных значений, количество дубликатов, основные описательные статистики и коэффициент вариации для количественных признаков. Эти результаты сохраняются в виде отдельных таблиц.

Четвертый этап направлен на выявление выбросов. Используются два подхода: биологически обоснованные пороги и статистический метод межквартильного размаха. Значения, выходящие за допустимые пределы, сохраняются в журнале выбросов и заменяются на пропущенные значения в очищенном датасете.

Пятый этап формирует данные для селекционного моделирования. Для доступных количественных признаков строятся линейные смешанные модели, где блок учитывается как фиксированный эффект, а генотип или линия рассматривается как случайный эффект. На выходе формируются таблицы компонент дисперсии и предварительные BLUP-оценки по линиям.

Шестой этап содержит обработку данных по сравнению методов экстракции высокомолекулярной ДНК. Сравниваются показатели выхода dsDNA, чистоты по соотношениям 260/280 и 260/230, а также целостности ДНК.

## 5. Выходные файлы

Результатом выполнения workflow являются очищенные таблицы данных, журналы выбросов, таблицы контроля качества, графики распределения пропущенных значений, boxplot-графики по блокам, таблицы компонент дисперсии и BLUP-оценки. Все результаты сохраняются в папках `data/processed`, `outputs/tables` и `outputs/figures`.

## 6. Воспроизводимость

Для повторения анализа необходимо поместить исходные CSV-файлы Field Book в папку `data/raw` и выполнить команду `source("R/run_all.R")` в RStudio. При сохранении структуры входных данных весь анализ выполняется автоматически, что позволяет использовать workflow для новых сезонов, последующих поколений F5-F7 и других культур.

## 7. Значение для селекционного анализа

Техническая реализация workflow позволяет минимизировать ошибки ручной обработки, повысить прозрачность фильтрации данных, формализовать критерии исключения выбросов и подготовить данные к интеграции с генотипической информацией. Это создает основу для последующего GWAS-анализа, геномной селекции и построения более точных селекционных моделей.
